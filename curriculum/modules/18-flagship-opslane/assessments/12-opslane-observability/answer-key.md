# Opslane Milestone 12 Assessment — Answer Key

## Multiple Choice (1 point each)

**1. b) Each unique combination of label key-value pairs creates a new distinct time-series in memory; unbounded cardinality causes exponential memory consumption and crashes the Prometheus scraper.**  
*Explanation:* Prometheus maintains time-series in memory indexed by the full metric name and label set. If `order_id` is a label and 1,000,000 orders are processed, 1,000,000 distinct time-series are instantiated, causing Prometheus to exhaust RAM (OOM) and crash.

**2. b) To partition observed execution times into duration ranges, enabling Prometheus to calculate accurate percentile latencies (p50, p90, p99) across time windows.**  
*Explanation:* Histograms sample observations (usually durations or payload sizes) and count them in configurable buckets. This allows operators to compute arbitrary quantiles (`histogram_quantile(0.99, ...)`) across clusters and arbitrary time intervals.

**3. a) Local registries avoid metric collision panics (`duplicate metrics collector registration attempted`) when tests run in parallel or instantiate multiple server instances.**  
*Explanation:* `prometheus.DefaultRegisterer` is a process-wide singleton. Calling `prometheus.MustRegister()` multiple times with the same metric name (such as when running parallel unit tests) panics. Creating an isolated `prometheus.NewRegistry()` per server instance provides hermetic test isolation.

**4. b) Generates an 8-byte cryptographically random hex string, injects it into the request context, and writes it to the response header.**  
*Explanation:* If an upstream service or client didn't supply an ID, the middleware generates a fresh random 16-character hexadecimal string, propagates it to the context, and echoes it in the `X-Correlation-ID` response header for client traceability.

**5. b) Gauge.**  
*Explanation:* A Gauge represents a numerical value that can arbitrarily go up and down (e.g. concurrent active goroutines, memory usage, queue depth). Counters can only increase monotonically.

**6. b) `GET /metrics`.**  
*Explanation:* `GET /metrics` is the conventional Prometheus scraping path mounted via `promhttp.HandlerFor()`.

## Short Answer (2 points each)

**7. Counter vs. Gauge vs. Histogram:**
- **Counter:** A cumulative metric that only ever increases (resets only on process restart). Example: `opslane_orders_processed_total` (counts total checkout attempts).
- **Gauge:** An instantaneous snapshot value that can arbitrarily increase or decrease. Example: `opslane_active_workers` (number of currently executing goroutines).
- **Histogram:** Samples observations into configurable buckets and counts occurrences. Example: `opslane_order_processing_duration_seconds` (measures latency distribution to compute p99 response times).
*Grading: 1 pt for distinguishing behavior (monotonic vs variable vs bucketed); 1 pt for accurate e-commerce examples.*

**8. Metric Cardinality in Prometheus:**
Cardinality is the total number of unique time-series generated by a metric. It is calculated as the Cartesian product of the number of possible values across all labels:
$$\text{Total Series} = \prod (\text{Unique Values per Label})$$
For example, a metric with 10 HTTP methods, 50 status codes, and 20 paths yields $10 \times 50 \times 20 = 10,000$ active series. If an unbounded label like `user_id` (1,000,000 users) is added, the cardinality explodes to $10,000,000,000$ series, crashing Prometheus.
*Grading: 1 pt for mathematical formula / Cartesian product explanation; 1 pt for explaining the memory failure mode.*

**9. Why average latency is misleading vs. p95/p99:**
- **Average Flaw:** An average masks catastrophic latency outliers. In an API with 1,000 requests where 990 take 10ms and 10 take 10 seconds, the average latency appears to be ~110ms ("fast"), even though 1% of users suffered an intolerable 10-second freeze.
- **SRE Priority on p95/p99:** The 99th percentile (p99) measures the latency experienced by the slowest 1% of requests. In high-traffic services, 1% of traffic affects thousands of customers. Optimizing p99 guarantees that tail latencies meet enterprise Service Level Agreements (SLAs).
*Grading: 1 pt for explaining how averages hide severe outliers; 1 pt for defining p99 and its significance for user experience and SLAs.*

**10. Request tracing with `slog` and `X-Correlation-ID`:**
When a request enters the API, the correlation middleware extracts or generates an `X-Correlation-ID` and stores it in `r.Context()`. As the request traverses handlers, service methods, and database repositories, every call to `slog.InfoContext` or `slog.ErrorContext` extracts the correlation ID from context and outputs it as an indexed JSON attribute (`"correlation_id": "abc-123"`). When an error occurs, an engineer searches the centralized log aggregator (Datadog, Elastic) for `correlation_id="abc-123"`, instantly surfacing every log line produced across all microservices for that exact request in chronological order.
*Grading: 1 pt for explaining context injection and structured attribute attachment; 1 pt for explaining centralized log filtering across service hops.*
